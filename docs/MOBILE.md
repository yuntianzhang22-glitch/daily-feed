# iPhone 移动内测

## 发给内测用户

用 iPhone 的 Safari 打开：

https://daily-feed-reader.pages.dev

输入私下收到的 `DF-XXXXX` 账号编号 → 登录 → 关注想看的人 → 保存关注 → 立即抓取。
无需 Mac、TestFlight 或 Apple 开发者账号。没有账号的用户请联系邀请人领取；网页不开放自行注册。

在 Safari 的分享菜单中选择「添加到主屏幕」，若出现「作为网页 App 打开」则保持开启。
操作说明参考 [Apple iPhone 使用手册](https://support.apple.com/zh-cn/guide/iphone/iphea86e5236/ios)。

浏览器构建目标是 Safari / iOS 16.4 及以上。发布前已用 Chromium 实际浏览器验收，仍需用目标 iPhone / iOS 真机确认 Safari、添加到主屏幕、系统键盘、安全区和视频播放。

## 支持范围

- 账号编号登录，兼容原有长凭证；身份、停用、额度、余额都由现有云端服务验证
- 关注推荐名单或手动添加 X 用户名，分组抓取最近的帖子
- 全部 / 未读 / 收藏、全文搜索、按来源筛选、时间 / 点赞排序、已读和收藏
- 完整正文、引用、转发、图片及行内视频；外部链接在新页面打开
- 本机 IndexedDB 保存账号各自的关注、内容与抓取进度；切换账号隔离数据
- 离线查看已抓取正文，联网抓取；图片和视频仍需网络
- 每天、工作日或每周指定日期的云端定时抓取；北京时间，显示下次和上次执行状态
- 主屏幕图标、独立窗口、深色模式、安全区、至少 44px 触控按钮和允许缩放的视口

账号、用量、额度和余额与桌面端共用。手机在「设置 → 定时抓取」选择开关、日期和北京时间后保存；计划按账号保存在云端，默认关闭，需用户自行开启。更改关注或抓取偏好后保存，会同时更新已开启的云端计划。
计划由每个账号独立的 Durable Object Alarm 执行，手机关闭、退出登录或锁屏后仍可运行。退出登录不会关闭计划；需要停止时先关闭定时开关并保存。频率和关注人数由服务端检查账号限制，抓取沿用现有账本授权和扣费。额度不足、余额不足或停用时不再调用上游；失败显示在上次执行状态中，按下一个计划时间再尝试。
任务先记录本次执行时间点，再发起上游请求，避免 Alarm 至少一次投递导致重复扣费。每个成功分组立即保存帖子和抓取进度，后续分组失败不丢失已完成内容。云端保留最近 500 条定时抓取结果；手机登录、回到页面或刷新状态时下载到本机，保留本机已有收藏和已读标记。手机上已下载的旧内容不随云端缓存淘汰而删除。
桌面端仍使用原有本机定时任务，不接入手机的云端计划。关注、手动抓取的帖子、收藏和已读暂不做完整的跨设备同步。
账号停用后，下一次在线验证会清除手机会话；已离线保存的内容无法由服务器远程抹除。
退出登录保留本机内容，再次登录同一账号即可查看；清除 Safari 网站数据会清除这些内容。
Safari 和主屏幕 Web App 的存储由系统管理，添加到主屏幕后如未继承会话，请再次登录并选择关注。

## 给内测用户发账号

账号管理沿用现有服务；管理员在自己的开发电脑运行：

```bash
npm run relay:admin:production -- add "手机内测用户名称"
```

只把新生成的账号编号和移动版网址私下发给对应用户。编号本身授予登录权限，不要把编号放在网址、公开群或截图中。已有内测用户直接使用原账号，不必重新创建。
账号限制、额度与停用管理见 `relay/README.md`；管理口令和供应商 API Key 不进入网页或安装包。

## 开发与验证

```bash
npm ci
npm run mobile:dev
```

打开终端显示的 `http://127.0.0.1:8794/mobile/`，使用同一终端显示的本地样例账号。这个环境只有合成帖子，不扣真实额度，不会连接正式账号或读取正式凭据。
它只监听电脑本机回环地址；给手机用户使用的是上面的线上 HTTPS 地址。

```bash
npm run mobile:build
npm run test:mobile
npm test
```

构建把现有客户端、关注抓取和帖子解析模块打包进浏览器产物，输出 `mobile/dist/mobile/`；图标复用项目已有图标，用 macOS 的 `sips` 缩放，构建电脑需为 Mac，使用者不需要。
`test:mobile` 使用真实 HTTP Worker / SQLite 账本、真实 workerd SQLite Durable Object / Alarm，以及隐藏浏览器验证后台执行、重复触发、分组失败保留、开关撤销、登录、持久化、离线导航、账号隔离和额度错误。布局测量覆盖 320×568、375×667、390×420、430×932 和 844×390，验证内容区、保存栏、导航不重叠，输入框至少 16px，长名单滚动后保存按钮仍能命中。
截图保存在 `.local/mobile-screenshots/`，不进开发源码包。

## 发布

手机用户使用独立入口 `daily-feed-reader.pages.dev`，在同一浏览器源访问页面和 API，不需要额外 CORS 或在手机配置服务地址。入口只转发固定的移动资源、状态、名单、抓取、定时设置与定时结果接口；不代理管理接口。资源和账号仍来自现有 Worker，所以日常移动版发布会自动反映到新入口，无需复制账号、凭据或数据库。
Cloudflare Static Assets 的 [绑定说明](https://developers.cloudflare.com/workers/static-assets/binding/) 解释了源站中资源的绑定。
根路径会转到 `/mobile/`；原 `/v1/*` 与 `/admin/*` 路由保留原有授权和响应。

```bash
npm run relay:deploy:production
```

该命令先构建移动版，再更新现有 Worker 及静态资源；不运行任何账号迁移、充值或密钥修改。
网络使用本机代理时，可按自己的代理配置给 CLI 设置 `HTTPS_PROXY` / `HTTP_PROXY`。
预发使用 `npm run relay:deploy:staging`，仍创建独立 Worker、KV 和账本。

独立入口本身的转发规则调整后，运行 `npm run mobile:deploy:entry` 发布。入口代码为 `mobile/entry-worker.mjs`，构建目录 `.local/mobile-entry/` 只包含入口 Worker 和公开 404 页面，不部署仓库或本地数据。账号级旧域名继续保留，既有 Mac 安装和旧手机入口仍可使用。

Service Worker 只缓存明确列出的应用静态资源；不会缓存 API、带 Authorization 的请求、外部媒体或管理接口。
缓存版本由全部资源内容的哈希决定。新版本安装完成后显示更新入口，用户点击后重新打开；抓取过程中会等待操作完成。

线上检查 `/mobile/`、`/mobile/app.js`、`/mobile/sw.js`、manifest 和图标返回正确类型；未登录的 `/v1/status` 仍为 401。新手机入口不提供管理接口（404），原管理服务仍要求管理员凭据（403）。
真机验收建议：Safari 打开并登录 → 保存关注并抓取 → 收藏/已读 → 添加到主屏幕 → 飞行模式重新打开 → 恢复网络 → 退出并重登。确认刘海与底部指示条不遮挡，键盘不自动放大输入框，竖屏、横屏和深色模式均可阅读。
