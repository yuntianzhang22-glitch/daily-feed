# 传统精选规则 rules-v1

当前首版用于实验和验收，不使用 LLM、向量或分类模型。分数表示规则估计的阅读优先级，不代表事实正确率或客观内容价值。九条正反馈只作为观察样本，不用于拟合权重或宣称效果提升。开源模型保留为后续备选。

## 如何使用

桌面和移动端都有「精选」入口。从当前筛选条件下最近的 500 条已保存帖子中，按规则排序并合并重复，展示前 20 条。展开「为什么推荐」可查看各项加分和扣分。精选采用规则排序，时间/热度排序选择暂时禁用；切回「全部」即可恢复常规阅读。全部帖子、收藏、已读不因精选而删除或改变。

设置中的「精选关注主题」可填 AI、产品设计等最多 20 个词，每词最多 40 个字符。留空时主题相关性取中性值，不假定所有用户都关注 AI。英文主题按词边界匹配，避免 AI 命中 chair；AI/人工智能附带一个有限的人工维护词典，含 ChatGPT、Claude、LLM 等，不能识别所有同义表达。

## 评分与调整

共享实现：`desktop/core/ranking.js`，桌面、浏览器和云端自动抓取均使用该模块。

```text
基础分 = 25×主题匹配 + 25×具体信息线索 + 20×来源线索
       + 15×解释方法线索 + 10×时效性 + 5×作者相对热度
推荐分 = clamp(基础分 - 互动诱导扣分 - 作者多样性扣分, 0, 100)
```

每项输入范围为 0～1，贡献有上限。修改权重集中编辑 `WEIGHTS`，规则或权重变化时应同时修改 `VERSION`，以便反馈数据区分算法版本。不要在不知道效果时直接根据少量正样本自动改权重。

- 主题：在正文、引用和作者名中匹配用户主动设置的词及有限词典。无主题取 0.5。
- 具体信息：方法、实验/结果、案例、带单位的数字、发布或变动等词语线索，各组只计一次并封顶。不因正文更长或重复堆词持续加分。
- 来源：论文/代码域名、其他 HTTPS 来源、第一人称发布表述和引用帖，分别给不同的线索分。域名、第一人称与引用均不是真实性认证，界面明确标注未核验。链接数量不会无限加分，无链接的一手发布也能获得来源线索分。
- 解释方法：方法、因果/局限/权衡、案例等词组命中。不能据此判断真实的论证深度。
- 时效：纯发布/变动线索按 2 天半衰期，其余内容按 7 天半衰期。时间缺失、无效或未来时间统一取 0.5，不制造最高时效。
- 相对热度：只比较同作者、相近帖龄分组的其他帖子；至少 4 个对照样本才启用。对点赞与转发做对数变换并封顶。样本不足取 0.5，低热度小作者不会因缺少数据被直接淘汰。
- 互动诱导：明显的抽奖/点赞转发诱导扣 20 分。普通产品发布、课程或商业内容不会仅因宣传性质自动扣分。
- 作者多样性：每新增一条同作者内容扣 10 分，最多 30 分；每次选择当前扣分后的最佳帖子，避免某个高产作者占满精选。

## 去重

同一原帖的转推合并；完全相同或词集合 Jaccard 相似度≥0.85 的内容保守合并。近似合并还要求外层解读也相似、链接/图片和数字一致，避免同一引用下的不同观点或不同版本被一起折叠。仅有相同外链不会合并。

此规则不理解深层语义，也不识别图片、视频内容，仍可能误合并或漏合并；「全部」保留原始帖子。代表卡片显示合并数量。

## 自动抓取

关注分组：先评估本次已返回的候选，随后按作者的保留上限（默认 3 条）入库。关键词搜索：在当前已返回页内先评分再按上限保留，不为跨页比较额外拉取内容。不会为算法增加接口页数或调用模型。

抓取费用仍按供应商返回内容计算，排序不能节约已经发生的返回量费用。API 未返回的帖子无法被本地算法找回，旧版之前因上限丢弃的内容也不会自动补抓。API 的 Top/Latest 控制候选获取方式，最终保留采用规则优选。

手机开启的云端计划会按账号保存并使用精选主题；旧计划没有主题时按中性值兼容。桌面本机计划使用本机设置。浏览器/桌面的阅读列表和主题不做完整跨设备同步。

## 反馈与验证

用户在精选中点击「有用/没帮助」时，后台记录 `algorithm_version=rules-v1`，并保存客户端提供的得分、规范化特征、当前权重与扣分。其他视图继续标记 baseline-v1。所有快照仍属于 client_reported，不是后端对帖子真实性的认证。

规则需要在同批候选的有用、普通、没帮助样本上比较；未标记不是负反馈。留出新的帖子做验证，检查前20条有用数量、重复率、作者覆盖和漏掉的低热度好帖子。比较时使用当时的内容、反馈时间和相同候选池，避免拿今天的热度或发布时间衰减重算过去并误判效果。

主要验收：`npm test`、`npm run test:mobile`、`npm run test:ui`。覆盖低热度研究、引用、无链接发布、重复和不同解读、版本数字、异常时间/互动量、主题保存、按作者截断、数据库状态保留及隐藏窗口中的真实精选交互。

## 部署状态

这次是传统算法首版代码与本地验收，尚未更新已安装应用或线上筛选规则。发布时需配套部署 Worker 和移动资源并打包桌面新版，完整源码/规则/测试随仓库一起发布。新增云端主题字段和评分反馈字段均向后兼容，不需要数据库迁移。Azure 翻译是已有独立功能，正式连接已实测正常；规则评分本身不调用翻译，也不消耗其额度。
